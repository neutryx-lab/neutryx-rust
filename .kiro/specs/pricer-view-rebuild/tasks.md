# Implementation Plan

## Phase 1: MVP — 商品選択 → CF展開 → 価格計算 → PV表示

- [ ] 1. 基盤: 定数・Pricer固有型・Piniaストアの構築
- [ ] 1.1 Pricer固有の定数と型を定義する
  - 確率モデル設定（GBM, Heston, Hull-White, CIR）の定数配列を定義し、各モデルのパラメータ名・ラベル・デフォルト値・範囲を含める
  - ディスカウントカーブ選択肢（USD-SOFR, EUR-ESTR, JPY-TONA, GBP-SONIA）の定数配列を定義する
  - 履歴エントリ、バリデーションエラー、計算メトリクス、サマリー統計、PV差分、比較結果、パラメータ変更、通貨集約の型定義を行う
  - _Requirements: 5.1, 5.2, 5.3, 12.6_

- [ ] 1.2 Pricer状態を一元管理するPiniaストアを構築する
  - 既存の `PricerState` インターフェースをベースに、商品選択・パラメータ・展開済み取引・編集・計算結果・設定・UI状態・履歴の全リアクティブ状態を定義する
  - アセットクラス別の商品グルーピング、選択中の商品、編集有無、サマリー統計、モデル設定、直近履歴、PV差分、比較結果、通貨集約のcomputed getterを定義する
  - 既存の `stores/config.ts` のComposition APIパターン（`defineStore` + `setup`関数）に従う
  - _Requirements: 12.2_
  - _Contracts: pricer store State_

- [ ] 2. コア Composable の実装
- [ ] 2.1 (P) 商品一覧の取得・選択・自動設定を行うcomposableを実装する
  - 既存の `fetchInstruments()` API関数を使用して商品一覧を取得し、ストアに格納する
  - IRS商品が一覧に含まれる場合、自動選択しUSD OIS 5Yデフォルトパラメータを設定する
  - 商品変更時に依存状態（パラメータ・展開済み取引・計算結果）をリセットするwatcherを設定する
  - 商品一覧取得失敗時にToast通知を表示し、`apiAvailable`をfalseに設定する
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 11.2_
  - _Contracts: useInstruments Service_

- [ ] 2.2 (P) キャッシュフロー編集状態の管理とプライシングリクエスト構築を行うcomposableを実装する
  - 個別キャッシュフローの想定元本・レート編集をストアの `editedCashflows` マップに反映する関数を提供する
  - 全編集の取り消し（リセット）機能を提供する
  - 展開済み取引のレグ・キャッシュフローに編集済み値を反映した `PricingLeg[]` を構築する関数を提供する
  - _Requirements: 3.1, 3.2, 3.4, 3.5_
  - _Contracts: useCashflowEditor Service_

- [ ] 2.3 プライシングフロー全体をオーケストレーションするcomposableを実装する
  - キャッシュフロー展開: パラメータバリデーション → 既存 `expandTrade()` API呼び出し → ストア更新の一連処理を提供する
  - 価格計算: 既存 `priceTrade()` と `calculateGreeks()` の並列実行 → ストア更新 → メトリクス記録の一連処理を提供する
  - バリデーション: 必須パラメータの存在・数値範囲チェックを行い、エラー配列を返す
  - 全状態リセット機能を提供する
  - 各操作の成功・失敗時にToast通知（`useToast`）で適切なフィードバックを行う
  - Greeks計算が失敗してもPV結果は有効として保持する（graceful degradation）
  - 2.1と2.2に依存する（商品ロードとCF編集の機能を利用）
  - _Requirements: 2.1, 3.5, 6.1, 7.3, 11.1, 11.3, 11.4, 12.3_
  - _Contracts: usePricer Service_

- [ ] 3. Phase 1 UIコンポーネントの実装
- [ ] 3.1 アセットクラス別グループ化ドロップダウンと動的パラメータフォームを実装する
  - 商品一覧をアセットクラスごとの `<optgroup>` にグループ化して表示する
  - 選択された商品の `requiredParams` に基づき、number/date/select/textフィールドを動的に生成する
  - バリデーションエラー発生時にフィールドを赤枠 + エラーメッセージで表示する
  - `useInstruments` composableを使用してストアと連携する
  - _Requirements: 1.1, 1.2, 1.4_

- [ ] 3.2 (P) 評価設定入力フォームを実装する
  - 評価日（デフォルト: 当日）の日付ピッカーを提供する
  - レポーティング通貨（USD, EUR, GBP, JPY）のドロップダウンを提供する
  - 「Use Default Model Config」トグルと、無効時のパス数・ステップ数入力を提供する
  - レートバンプ（bp）、FXバンプ（%）、ボルバンプ（%）の入力を提供する
  - ストアの該当フィールドと双方向バインドする
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [ ] 3.3 (P) PV表示コンポーネントを実装する
  - トータルPVを正値（success色）/負値（danger色）で大きく表示する
  - レグ別PV内訳を方向・通貨ラベル付きで表示する
  - 複数通貨のレグが存在する場合に通貨別PV集約セクションを表示する
  - 前回結果との差分（絶対値・パーセント）を表示する
  - 既存の `formatCurrency` ユーティリティを使用する
  - _Requirements: 6.4, 6.5, 6.6, 10.4, 12.5_

- [ ] 3.4 キャッシュフローテーブルを実装する
  - レグ別テーブルで各レグのヘッダーに方向・通貨・レグタイプ・レートインデックスのバッジを表示する
  - 各行に支払日・発生期間・年数分・想定元本・レート・ペイオフタイプ・DF（計算後）・PV（計算後）を表示する
  - 想定元本のインライン編集を K/M/B コンパクトフォーマットで提供する（既存 `formatNumberCompact`/`parseFormattedNumber` を使用）
  - 固定レートのインライン編集をパーセント表示で提供する
  - 編集済みセルを黄色ハイライトし、ヘッダーに「Modified」インジケータと「Reset Edits」ボタンを表示する
  - ローディング中はスケルトンアニメーション、未展開時は空状態プレースホルダーを表示する
  - フッターにレグ数・キャッシュフロー数・処理時間のメタデータを表示する
  - `useCashflowEditor` composableを使用してストアと連携する
  - _Requirements: 2.2, 2.3, 2.4, 2.5, 2.6, 3.1, 3.2, 3.3, 3.4, 12.5_

- [ ] 3.5 アクションボタン群を実装する
  - 「Expand Cashflows」「Price & Risks」「Reset」の3ボタンを提供する
  - 商品未選択時にExpandを無効化、展開済み取引未存在時にPriceを無効化する
  - 処理中はスピナーアイコンと進行中テキスト（「Expanding...」「Calculating...」）を表示する
  - `usePricer` composableのメソッドを呼び出す
  - _Requirements: 2.1, 6.1, 6.2, 6.3_

- [ ] 4. PricerView MVPオーケストレータの統合
- [ ] 4.1 Phase 1のサブコンポーネントを合成するPricerViewオーケストレータを構築する
  - 3カラムグリッドレイアウト（左1/3: 設定パネル、右2/3: キャッシュフロー）を構成する
  - `onMounted` で商品一覧のロードをトリガーする
  - API利用不可時のフォールバック画面を表示する
  - 既存の `glass-card` デザインシステムに準拠する
  - 200行以内に収め、ロジックはcomposable/storeに委譲する
  - 既存のルーター設定（`/pricer` → `PricerView`）に変更を加えない
  - _Requirements: 1.1, 1.3, 11.2, 12.1, 12.3, 12.4, 12.5, 13.1, 13.2, 13.3_

## Phase 2: Greeks・メトリクス・サマリー・マーケットデータ/モデル選択

- [ ] 5. Phase 2 UIコンポーネントの実装
- [ ] 5.1 (P) Greeks表示コンポーネントを実装する
  - DV01・ガンマ・シータ・ベガを2x2グリッドで表示する
  - 各Greekに正値/負値の色分けを適用する
  - null値のGreekは表示しない
  - 既存の `formatCurrency` を使用する
  - _Requirements: 7.1, 7.2, 12.5_

- [ ] 5.2 (P) 計算メトリクスバーを実装する
  - 処理時間（ミリ秒）、使用モデル、タイムスタンプを1行バーで表示する
  - 計算未実行時は非表示とする
  - _Requirements: 8.1_

- [ ] 5.3 (P) サマリー統計カード行を実装する
  - 評価日・商品名・PV・DV01の4つのカードをアイコン・色分け付きで表示する
  - 計算結果が存在しない場合はPV・DV01カードにプレースホルダー「-」を表示する
  - _Requirements: 9.1, 9.2_

- [ ] 5.4 (P) ディスカウントカーブ選択ドロップダウンを実装する
  - 定数のカーブ選択肢からドロップダウンを生成する
  - ストアの `selectedCurveIndex` と双方向バインドする
  - _Requirements: 5.1_

- [ ] 5.5 (P) 確率モデル選択と動的パラメータフォームを実装する
  - モデルタイプドロップダウン（GBM, Heston, Hull-White, CIR）を提供する
  - 選択されたモデルのパラメータフォームを動的に生成し、各パラメータにmin/max/stepバリデーションを適用する
  - モデル変更時にデフォルト値にリセットするwatcherを設定する
  - _Requirements: 5.2, 5.3_

- [ ] 5.6 設定パネルと結果パネルのwrapperコンポーネントを作成し、Phase 2コンポーネントをPricerViewに統合する
  - 設定パネルwrapperに商品選択・評価設定・マーケットデータ・モデル選択・アクションをグルーピングする
  - 結果パネルwrapperにPV表示・Greeks・メトリクスをグルーピングする
  - PricerViewにサマリーバーとPhase 2コンポーネントを追加する
  - _Requirements: 13.1, 13.2_

## Phase 3: 結果履歴・比較モード

- [ ] 6. 結果履歴管理と比較機能の実装
- [ ] 6.1 結果履歴を管理するcomposableを実装する
  - 計算成功時に現在のパラメータ・PV・Greeks・設定情報をまとめた履歴エントリをストアに追加する（最大5件保持、FIFO）
  - 指定した履歴エントリの全パラメータ・結果をストアに復元する機能を提供する
  - 比較モードの切り替えと比較対象の選択を管理する
  - _Requirements: 10.1, 10.3_
  - _Contracts: usePricerHistory Service_

- [ ] 6.2 履歴リスト・復元・比較モードUIを実装する
  - 直近の履歴エントリを商品名・タイムスタンプ・PV付きのクリッカブルリストで表示する
  - クリック時に当該エントリのパラメータと結果を画面に復元し、Toast通知を表示する
  - 2件以上の履歴が存在する場合に比較モードトグルを表示する
  - 比較モードでは2件の結果のPVを並列表示し、変更されたパラメータをハイライトする
  - _Requirements: 10.2, 10.3, 10.4, 10.5_

- [ ] 6.3 usePricerをusePricerHistoryと連携させ、計算成功時の自動履歴追加を有効にする
  - `calculateAll()` の成功パスに `addToHistory()` 呼び出しを追加する
  - PricerViewにPricerHistoryコンポーネントを統合する
  - _Requirements: 10.1_

## Phase 4: ビルド検証

- [ ] 7. ビルド・型チェック・動作確認を実行する
  - TypeScript型チェック（`vue-tsc --noEmit`）でエラーがないことを確認する
  - 本番ビルド（`npm run build`）が成功することを確認する
  - ブラウザでの手動動作確認: 商品選択 → パラメータ入力 → CF展開 → 価格計算 → PV/Greeks表示 → 履歴/比較のE2Eフローを検証する
  - コンソールエラーがないことを確認する
  - _Requirements: 12.1, 12.2, 12.3, 12.4, 12.5, 12.6_
